## 技术决定

当前机器无 Unity 编辑器，也无 .NET SDK，但有 .NET Framework C# 编译器。因此使用同一份 Core 源码，提供轻量的 Windows 试玩宿主与后续 Unity 3D 宿主。原生预览器不承担正式网络架构。

Core 不依赖 Unity，位置使用每格1000单位的整数坐标、20Hz固定步长。寻路是四方向带墙体成本的 A*；部队实际拆墙后才能穿过对应路径。选目标有兵种偏好，但尚未做整条路径成本参与目标排序，也没有部队避让。

关卡预设容易，主要用于验证行为。自动化全兵力进攻可以通过三个关卡，不能据此宣称数值平衡完成。尚未设置失败次数、难度自适应或付费设计。

`Core/ModelGeometry.cs` 定义引擎无关的三维面和顶点色，程序化生成 7 类建筑的三级模型及 4 类兵种。原生预览器投影、遮面、排序、打光后以 2 倍采样缓存模型精灵；Unity `ModelViews.cs` 从同一几何生成网格，使用 URP 顶点色光照材质。这样后续改善模型可同时影响两个宿主。原生地形单独缓存，未接入骨骼动画。

建筑上限统一由 `Rules.BuildLimit` 按议事堡等级决定，UI 只是展示，实际限制在 `GameSession.Build`。不在读档校验中强制新数量上限，避免删除旧版建筑。拆除先收取已有收益，再按建设和历次升级总投入返还 50%；保护议事堡，清空移动历史，持久化仍使用原来的 XML 版本 1。

图鉴和战斗说明读取真实的 `TroopSpec` 数值，不使用另一套展示数值。教学引导铁卫吸引火力、破城手开墙、先锋跟进、游侠后排输出；首次出征教学按进程显示一次，不新增存档字段。模态面板暂停本地战斗，并阻止点击穿透。
